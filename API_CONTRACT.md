# Fable API contract

This contract describes the security-hardened API. Swagger at `/docs` contains the
complete generated schemas.

## Authentication

Every route below requires `Authorization: Bearer <key>`. Missing or invalid keys
return `401`; a valid key without the required scope returns `403`; a server with no
`FABLE_API_KEYS` configuration returns `503`. `/health` is the sole public route.

Bearer keys map to the roles documented in [README.md](README.md). Employee names and
internal database actor IDs are not part of any response schema. Entities are
identified by opaque `entity_ref` and `actor_ref` strings.

### Event-level risk contract

For every event, the case detail response includes `event_risk_breakdown` with:

- `raw_risk`, `context_credit`, and `residual_before_floor`;
- `critical_floor`, `critical_reasons`, and final `residual_contribution`;
- `marginal_case_contribution`, computed by removing that event from case noisy-OR;
- `categories`, including raw fields, constituent signals, source, and within-group maximum.

The non-suppressible floor is exactly `25.0` percentage points for:

- action `privilege_change`;
- action `file_download` with `volume >= 1000`;
- every `external_upload`; an external-looking destination additionally emits the
  `external_destination` reason.

Within each event category, correlated signals use `max`. Noisy-OR is applied only
across categories and then across event residuals.

Signal metadata distinguishes `rule_based` inputs, the offline learned Isolation
Forest, and k-means cohort deviation. K-means assignment excludes the most recent
seven days and falls back to the entity's role group whenever the computed cluster
contains fewer than three members.

## Context lifecycle

`POST /entities/{entity_ref}/context` accepts:

```json
{
  "reason": "project",
  "effective_from": "2026-09-01T00:00:00Z",
  "effective_until": "2026-10-01T00:00:00Z",
  "allowed_resources": ["migration-repo"],
  "allowed_actions": ["repo_access"],
  "approved_destinations": null,
  "supersedes_id": 2
}
```

It returns `202` and an append-only entry with `approval_state: "pending"`.
Caller-supplied approver identity is not accepted. A pending entry does not affect
case state.

`POST /context/{entry_id}/review` accepts one of:

```json
{"decision":"approved","note":"Change ticket verified"}
```

```json
{"decision":"rejected","note":"Scope does not match ticket"}
```

The reviewer must have `context:approve` and must differ from the proposer. Approval
atomically activates the new revision, supersedes its predecessor when specified,
reassesses affected cases, appends case-assessment history, and records an audit log.
Repeated review returns `409`.

## Assessment guarantees

- `raw_deviation` does not depend on context.
- `context_coverage = Σ(raw_event_risk × event_credit) / Σ(raw_event_risk)`.
- Event residuals are fused with noisy-OR; critical floors survive full coverage.
- Indeterminate events remain represented with zero coverage credit.
- Case GET requests return committed snapshots and never recompute state.
- Case detail exposes immutable `original_assessment` and `current_assessment`.
- Late approved context is visible per match and can raise
  `retroactive_justification_review` when coverage rises by at least `0.25`.
- `case_events` provides referential evidence membership and `case_assessments`
  records immutable versions with their input event/context IDs.

## Response control plane

The response layer is a **Policy-bounded autonomous protective hold**, not autonomous
punishment or intent determination. It consumes committed assessments without
recomputing them. No LLM output is a policy input and no LLM can authorize or execute
an action.

Central policy constants:

| Setting | Value |
|---|---:|
| Automatic protective-hold priority threshold | `75.0` residual risk |
| Independent evidence requirement | `2` categories, or one decisive critical hard rule |
| Protective-hold TTL | `15 minutes` |
| Step-up-auth TTL | `5 minutes` |
| Scoring contract recorded on actions | `event-fusion-v2` |

`observe` and `step_up_auth` may be auto-authorized. The narrowly scoped
`block_external_upload`, `freeze_privilege_change`, and `rate_limit_download`
controls may be auto-authorized only when all safeguards pass. `revoke_session`,
`isolate_device`, and `disable_account` always require an independent
`response_approver`; a requester cannot approve their own request.

Response statuses are `proposed`, `auto_authorized`, `awaiting_approval`,
`approved`, `executing`, `active`, `expired`, `rolled_back`, `failed`,
and `rejected`. Invalid transitions return `409`. Terminal actions cannot become
active again. The unique `idempotency_key` makes request and execution retry-safe.

Every action records the committed assessment ID, scoring version, trigger events,
policy rule and reasons, evidence categories, target scope, blast radius, approval
state, timestamps, execution verification, rollback result, and immutable transition
history. Clients cannot submit risks, policy decisions, or approval requirements.

The default and only implemented adapter is `sandbox`. It persists and verifies
simulated control state. A lifespan worker applies due expirations separately from
read requests. The adapter never claims real Okta, Entra, firewall, endpoint, or
cloud enforcement. Non-sandbox startup is rejected; fake production connectors are
not provided.

Evidence graphs contain entity, device, inferred session, resource, privilege,
destination, context, case, and response-action nodes when supported by persisted
evidence. NetworkX performs shortest-path and cycle analysis. Paths are labeled
evidence/observed-activity paths, never proven causality.

## CORS

Defaults permit `http://localhost:3000` and `http://127.0.0.1:3000`, without
credentials. Configure origins with `FABLE_CORS_ORIGINS` and credential behavior
with `FABLE_CORS_ALLOW_CREDENTIALS`. Wildcard plus credentials is rejected at
startup.
